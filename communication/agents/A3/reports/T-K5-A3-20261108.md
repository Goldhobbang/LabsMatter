## 2. WIFI finding — not a defect

K4 reported `wireless_active = 0` for a WIFI+conductor layout. Investigation:

- `wifi_update` matches `WIFI.cpp`: it reads/writes the persistent
  `Sim::wireless` store, keys the channel from temperature, emits
  `PSCN`/`NSCN`/`INWR` when the channel is active, and raises `note_spark` when
  an adjacent `SPRK` has `life >= 3` and `ctype != NSCN`.
- `Sim::after_sim` promotes `wireless[ch][1] -> [0]` once per tick.
- The K4 layout had **no spark source**. Placing WIFI is not a signal
  (per the reference). A battery-driven spark is required to transmit and a
  `PSCN`/`NSCN`/`INWR` is required at the receiver.

Verified against the built WASM bundle:

```
BTRY -> METL -> WIFI(tx) ... WIFI(rx) -> NSCN -> METL
WIFI active>0 true, max 1, receiver_spark true
```

Conclusion: WIFI activation is correct; the K4 observation lacked electrical
activation. No second store was created.

## 3. Completed element behavior

### PIPE / PPIP (`pipe_update`)

- One-slot payload storage in `ctype`/`temp`/`tmp2`/`tmp3`/`tmp4` (type, temp,
  life, tmp, ctype), preserved on output (`pipe_to_part`).
- Intake of neighbouring `TYPE_PART/LIQUID/GAS/ENERGY`, SOAP detachment, and
  `STOR` payload hand-off. Pipes do not absorb solids.
- Directional transport with a deterministic flow field in free `tmp` bits
  20..22 (continues straight, then turns), depth-limited to 2 hops per frame
  like the reference `pushParticle`.
- Output at an open neighbour; `PRTI` hand-off into `Sim.portal`.
- PPIP triggers: `TRIGGER_ON`/`OFF`/`REVERSE` flags set pause/reverse, and
  adjacent `BRCK` glow is toggled.
- Unconfigured pipes generate their `BRCK` border and initialise to RED, then
  propagate the reference colour gradient.
- `PPIP` is now dispatched to the same handler (`pt::PIPE | pt::PPIP`).

WASM evidence: after auto-configuration, a `PIPE` line absorbs an adjacent
`SAND` (`element_count(SAND) -> 0`). Native check: sand traverses a configured
line and is emitted past the open end.

### PSTN (`pstn_update`)

- Temperature-derived piston count (`floor((temp-268.15)/10)` cells/frame).
- `tmp3` flags honoured: `EXT_OBSTACLE`, `EXT_ARMLIMIT`, `RET_OBSTACLE`,
  `RET_TOOSHORT`.
- Extension/retraction through `can_move_stack`/`move_stack`; no obstructing
  particle is deleted.
- `FRME` row in front is displaced as a stack before the arm moves.
- Native evidence: `PSTN` 1 -> 4 particles on PSCN spark, 4 -> 3 on NSCN spark.

### SOAP (`soap_update`)

- Bubble formation under pressure, persistent links in `tmp`/`tmp2` with
  `ctype` bits `0x02`/`0x04`.
- Invalid-link cleanup, chain detach on pop, obstacle/wall pop when life is
  exhausted, `GLAS` exemption.
- First-order and second-order distance constraints.
- Native evidence: 10 pressurised SOAP particles form 10 bubbles and 10 links.

### STKM / STKM2 (`stickman_tick`)

- Hazard scan: ACID/LAVA/virus are lethal; FIRE/PLSM/DEADLY cause damage and
  eventually death.
- Leg phase (walking vs standing) stored in `PlayerState::legs`.
- Element power spawn via the existing `SPAWN` input bit and `player.elem`.
- Death clears `spwn` so the entity can be respawned; players remain independent.
- Locomotion still uses `step_entity_at` (Agent 1's tile-based movement).

### FIGH (`figh_update`)

- Acquires the nearest `STKM`/`STKM2` within 48 px, pursues with the shared
  input bits, and melees on a cadence.
- Hazard damage and death cleanup clear the fighter slot and `figh_count`.
- Idle wander when no target.
- Native evidence: fighter closes to dx=1 and kills the stickman; `figh_count`
  remains 1 after the fighter survives.
